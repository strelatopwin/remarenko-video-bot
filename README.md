# Remarenko Кружечки

Telegram-бот для відеоповідомлень. Надішли відео в особистий чат із ботом, і він відповість кружечком зі звуком. Бот кадрує відео по центру до 640 × 640. Довгі ролики пропонує обрізати в Telegram.

## Запуск із файлами до 200 МБ

1. У [@BotFather](https://t.me/BotFather) виконай `/newbot`. Назва може бути **Remarenko Кружечки**, а username — `RemarenkoVideoBot`, якщо вільний.
2. На [my.telegram.org](https://my.telegram.org) відкрий **API development tools** та отримай `api_id` і `api_hash`.
3. Розпакуй архів на комп’ютері або VPS із Docker та Docker Compose. У папці проєкту виконай `cp .env.example .env`. Заповни в `.env` значення `BOT_TOKEN`, `TELEGRAM_API_ID` і `TELEGRAM_API_HASH`. Зберігай їх у себе або в секретах хостингу.
4. Якщо бот потрібен лише тобі або команді, заповни `ALLOWED_USER_IDS` числовими Telegram ID через кому. Порожнє поле відкриває бот для всіх, хто має його посилання.
5. Запусти `docker compose up -d --build`. Журнал бота доступний через `docker compose logs -f bot`.
6. Відкрий свого бота в Telegram, натисни **Почати** й надішли тестове відео тривалістю до 60 секунд.

У цьому режимі бот використовує локальний Telegram Bot API і приймає ролики розміром як у прикладі на 41,6 МБ. Якщо цей самий токен раніше використовувався з публічним Bot API, спочатку виклич метод [logOut](https://core.telegram.org/bots/api#logout) на публічному API.

Бот видаляє свої тимчасові файли після обробки. Локальний Telegram Bot API зберігає власний кеш на томі `telegram-data`. Для публічного запуску стеж за вільним місцем на диску.

## Простий запуск із файлами до 20 МБ

Для тесту через публічний Telegram Bot API вистачить одного токена. Встанови Python 3.10+, FFmpeg і FFprobe та виконай `python -m pip install -r requirements.txt`. Задай `BOT_TOKEN` у змінних середовища й запусти `python bot.py`. Не запускай одночасно два процеси з одним токеном.

## Запуск через GitHub і Railway

1. Створи бота через `/newbot` у BotFather. Отримай `api_id` та `api_hash` на my.telegram.org, у **API development tools**.
2. Створи окремий приватний репозиторій GitHub і завантаж файли з розпакованого архіву в корінь репозиторію. Файл `.env.example` містить лише назви змінних. Файл `.env` із реальними значеннями в GitHub не завантажуй.
3. У Railway створи сервіс із цього GitHub-репозиторію. Файл `railway.toml` вибере `Dockerfile.railway`. Публічний домен для бота не потрібен.
4. У **Variables** додай `BOT_TOKEN`, `TELEGRAM_API_ID`, `TELEGRAM_API_HASH` та, за потреби, `ALLOWED_USER_IDS`. Для бота використовуй один екземпляр сервісу. Для нового токена переходити з публічного Bot API не потрібно, якщо ти ще його там не використовував.
5. Запусти деплой. Дочекайся повідомлення «Бот готовий приймати відео до 200 МБ» у **Deploy Logs**. У Telegram надішли `/start`, потім відео до 60 секунд. Щоб перевірити обробку оригіналу, надішли ролик як файл.
6. Перевір відтворення й звук у Telegram. Бот кодує кружечки у 640 × 640, H.264 з CRF 16 та AAC до 192 кбіт/с. Роздільність джерела визначає, скільки деталей можна зберегти.

На Railway бот і локальний Telegram Bot API працюють в одному контейнері, тому бот може читати отримані файли прямо з диска. Кеш використовує диск контейнера. Для цього бота база даних не потрібна.
